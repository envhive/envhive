# 蜂巢 EnvHive 界面重构设计文档（v2）

> 状态：**设计稿 v1.2**（2026-08-06）—— 信息架构与界面方案（已并入两轮评审修订，见 [第 9 章](#9-评审修订记录v11--v12)）；待确认后按 [第 7 章](#7-实施顺序建议-4-个阶段) 落地实施
> 目标：把当前 9 页平铺的杂乱结构，收敛为 **7 个清晰的业务页面**；让「查找功能」变成「直觉导航」。
> 关联文档：[roadmap.md](roadmap.md)（功能清单）、[lua-plugin-v2-design.md](lua-plugin-v2-design.md)（插件协议）

## 1. 现状与问题

### 1.1 当前导航结构（9 页平铺）

```
总览          首页 · 环境变量
工具管理     工具列表 · 下载队列
网络          镜像与仓库 · 代理与加速
环境与偏好    导入导出 · 设置
扩展与维护    插件与 Lua · 统计
```

### 1.2 现存问题

| # | 问题 | 表现 |
|---|------|------|
| 1 | **功能粒度过细** | 「下载队列」是工具管理的子流程，却独立成页，页面间来回跳 |
| 2 | **分组语义混乱** | 「网络」里只有镜像/代理，但下载代理与工具安装强相关；「导入导出」单独成页偏轻 |
| 3 | **日志被埋没** | 日志藏在「设置」底部，排障时难以发现 |
| 4 | **首页信息密度失衡** | 首页=全量环境变量表，新人看不懂「当前系统在用哪些工具」 |
| 5 | **缺少状态可见性** | 系统代理、镜像源、插件健康度没有全局状态出口 |

## 2. 设计目标与原则

1. **页面即任务**：一个页面 = 一个用户任务（看现状 / 管工具/ 调网络 / 设偏好 / 管插件 / 维护 / 排障）。
2. **合并子流程**：队列、导入导出等「子流程」下沉为页内面板/抽屉，不再占用一级导航。
3. **首页回答"我在用什么"**：第一屏必须是「当前生效的工具及其版本」，可原地切换。
4. **全局 / 项目分离**：全局环境 = 写系统变量，应用一次整机生效，用户自己开 cmd 即可（**无需启动功能**）；项目环境 = 会话级注入，仅对启动的终端/IDE 生效 —— 「以此环境启动」只属于项目/会话场景。
5. **统一主色**：全站统一使用品牌紫 `#534ab7` 作为主色调（Logo/顶栏/主按钮/导航激活态/页标题图标），保持视觉一致。
6. **组件化**：前端按页拆分组件，杜绝 App.tsx 继续膨胀（当前单文件 ~69KB）。

## 4. 全局设计语言

### 4.1 布局框架（保持不变，微调）

```
┌────────────────────────────────────────────────────────┐
│ TopBar：品牌 + 全局状态（平台/存储可写）+ 刷新 + 应用为系统环境变量 │
├──────────┬─────────────────────────────────────────────┤
│ Sidebar  │ Content                                     │
│ 7 项导航  │ 页面标题 + 页内区块                            │
└──────────┴─────────────────────────────────────────────┘
```

- 顶栏常驻：品牌区、环境徽标（平台/架构/存储可写性）、「应用为系统环境变量」主按钮（写系统变量的全局出口）、「刷新」次按钮、进度条（全局下载进度）。「以此环境启动」已移出顶栏，归入首页「项目环境」区。
- 侧边栏：宽 300px，7 个导航项，**激活项统一使用品牌紫** `#534ab7`（底 + 字），未激活项使用中性灰，保持视觉统一克制。
- 内容区：统一 `section` 卡片化，页面标题行带图标 + 说明 + 主操作按钮。

### 4.2 主色系统

| 用途 | 色值 | 说明 |
|------|------|------|
| 品牌主色 | `#534ab7` | Logo / 顶栏 / 主按钮 / 导航激活态 / 页标题图标 |
| 中性灰（未激活） | `#9ca3af` | 导航未激活项、次要文字 |
| 状态语义色 | 绿 `#16a34a` / 橙 `#ef9f27` / 红 `#e05252` / 灰 `#9ca3af` | 仅用于状态徽标（已安装/当前使用/有新版本/冲突/未安装），不作页面身份色 |

> 全站统一使用品牌紫 `#534ab7` 作为主色调，不再为每个页面分配独立身份色，避免页面切换时色彩轮换造成的视觉杂乱。状态语义色仅在徽标等局部场景使用。

### 4.3 通用组件规范

| 组件 | 规格 |
|------|------|
| 页面标题行 | 图标（品牌紫）+ 标题 + 右侧主操作按钮（btn-primary） |
| 区块（section） | 白卡片、`--border` 描边、圆角 14px、内边距 20px |
|工具卡片 | 图标 + 名称/类别 + 当前版本徽标 + 发行商下拉 + 版本下拉 + 操作按钮组 |
| 项目预设行 | 项目名 + 目录 + 版本组合 chips（品牌紫）+ [启动终端][启动 IDE][复制脚本][编辑] |
| 版本组合选择器 | 每工具一行：名称 + 版本下拉（多发行商再加发行商下拉）+ 移除；「从全局克隆」一键带入当前全局版本 |
| 状态徽标（chip） | 已安装=绿、当前使用=紫、有新版本=橙、冲突=红、未安装=灰；全局同步态=已生效绿/未同步橙/需重启红 |
| 表格（环境变量/统计） | 等宽字体值、斑马纹、可复制 |
| 队列任务行 | 图标 +工具/版本 + 状态徽标 + 进度条 + 操作 |
| Skeleton（加载中） | 区块级灰色占位骨架，列表/卡片统一尺寸 |
| EmptyState（空状态） | 图标 + 说明 + 引导按钮（如「前往工具管理安装」） |
| ErrorState（错误态） | 后端未连接 / 命令失败提示 + 重试按钮；预览模式统一横幅 |
| Toast | 沿用现有 5s 自动消失 |

## 5. 页面详细设计

### 5.1 首页 · 环境总览（全局 + 项目）

**目标**：3 秒回答「系统现在用着哪些工具、什么版本、环境变量如何」；全局区可原地切换并应用为系统变量，项目区按预设版本组合启动会话。

**布局线框**

```
┌─────────────────────────────────────────────────────┐
│ 首页 · 环境总览                   [应用为系统环境变量]  │
├─────────────────────────────────────────────────────┤
│ ┌─ 全局环境（系统级）──────────────────────────────┐ │
│ │ 生效工具4 · 环境变量 23 · PATH 条目 9  [未同步]  │ │
│ │ ┌──────────────┐ ┌──────────────┐ ┌──────────┐  │ │
│ │ │ ● Node v22.14│ │ ● Java 26.0.2│ │ ● Go     │  │ │
│ │ │  [v22 ▾] [切换] │ [zulu▾][26▾][切换]│ 1.24.3  │  │ │
│ │ └──────────────┘ └──────────────┘ └──────────┘  │ │
│ │ 环境变量总览（折叠，默认收拢）       [展开 ∨]       │ │
│ └───────────────────────────────────────────────┘ │
│ ┌─ 项目环境（会话级）──────── [从全局克隆] [新建预设] ─┐ │
│ │ order-service   D:\work\order-service           │ │
│ │  java 18 · node 22  [启动终端][启动 IDE][编辑]   │ │
│ │ data-platform   D:\work\data-platform           │ │
│ │  node 22 · go 1.24  [启动终端][启动 IDE][编辑]   │ │
│ │ 空状态：无预设 → EmptyState「新建第一个项目环境」   │ │
│ └───────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────┘
```

**交互要点**
- **全局环境（系统级）**：工具卡片仅展示已激活或已安装的工具；版本下拉直连 `list_versions`，选后「切换」更新当前选择；主操作「应用为系统环境变量」写入系统变量（Windows 需管理员权限；已打开的窗口不生效、需重开）——应用后用户自己开 cmd 即可，**本区不提供启动功能**。
- **同步状态徽标**：对比「当前选择」与「系统实际值」，三态：已生效=绿 / 未同步=橙（切换后未应用）/ 需重启或权限不足=红。
- **项目环境（会话级）**：项目 = 目录 + 命名 + 版本组合预设；「启动终端 / 启动 IDE」通过 `launch_session` 注入该组合的环境变量（JAVA_HOME、PATH 指向预设版本），不写系统变量，关窗即消失；「复制脚本」生成可粘贴的注入脚本（cmd / PowerShell）。
- **新建/编辑预设**：弹出版本组合选择器（见 4.3），每个工具一行选版本；「从全局克隆」把当前全局版本一键带入再改。
- 首页工具卡片动作收敛：只保留「切换」；卸载、版本详情等低频操作通过「管理 →」锚点跳转工具管理（`setPage("tools")` + 滚动定位）。
- 环境变量表默认折叠，展开后为 `key / value / 来源(工具)` 三列，支持复制单行。
- 空状态：全局区无已安装工具→ EmptyState（引导「前往工具管理」安装）；项目区无预设 → EmptyState「新建第一个项目环境」。

**所需后端命令**：`list_tools`、`home_overview`（已有）、`switch_env`、`apply_global_env`（写系统变量，新增）、`list_projects` / `save_project` / `delete_project`（项目预设 CRUD，新增）、`launch_session`（已有）。

### 5.2工具管理

**目标**：安装 / 切换 / 卸载的完整工作台，含发行商×版本两级选择与下载队列。

**布局线框**

```
┌─────────────────────────────────────────────────────┐
│工具管理                              [批量安装] [刷新] │
├─────────────────────────────────────────────────────┤
│ 筛选：[全部 ▾] [搜索工具...]  已装 5 · 有新版本 2       │
│ ┌─工具卡片 ──────────────────────────────────────┐  │
│ │ [图标] Java · language                          │  │
│ │   发行商 [zulu ▾]  版本 [26.0.2.fx-zulu ▾]       │  │
│ │   已安装: 21.0.5-zulu ✔  26.0.2-zulu ✔ (当前)    │  │
│ │   [安装所选] [切换] [卸载…]   ⚠ 新版本 26.0.3      │  │
└─────────────────────────────────────────────────────┘
（下载队列为全局悬浮抽屉，挂 App 壳层 —— 任何页面右下角
 浮动按钮打开，按钮带进行中任务数角标；见下方交互要点）
```

**交互要点**
- **发行商 × 版本两级联动**：选择发行商后拉取该发行商版本列表；版本标识符 SDKMAN 风格，`fx` 变体打「FX」徽标。
- **已安装版本列表**：胶囊式展示，当前激活版本高亮 + 「当前」徽标；**点击胶囊展开一行详情（评审修订）**：版本号、占用大小、安装日期、该版本注入的环境变量（JAVA_HOME 等），行尾「切换/卸载」。
- **卸载（评审修订，防误删）**：确认框除二次确认外，**明确列出将移除的环境变量注入项**；当前激活版本不可卸载（按钮禁用 + 提示）；卸载按钮永远指向确认展开的版本，而非下拉中选中的版本。
- **队列抽屉（评审修订，全局化）**：不再内嵌于工具管理页 —— 提升为 **App 壳层全局悬浮抽屉**，任何页面右下角悬浮按钮（带进行中任务数角标）打开；任务支持 排队/执行中/完成/失败/取消，失败可「重试」。
- **新版本通知**：卡片右上角橙色徽标；顶部通知条保留「一键更新全部」。

**所需后端命令**：`list_tools`、`list_versions`、`install_tool`、`switch_env`、`uninstall_tool`、`queue_status`、`queue_cancel`、`check_updates`（已有）。

### 5.3 网络 · 镜像与代理

**目标**：镜像切换、代理设置两个高频操作集中在一页，分两个主区块。

**布局线框**

```
┌─────────────────────────────────────────────────────┐
│ 网络 · 镜像与代理                                     │
├─────────────────────────────────────────────────────┤
│ 镜像源一键切换                                        │
│ ┌───────────────────────────────────────────────┐   │
│ │ npm       registry.npmmirror.com   [官方 ▾] ✓ │   │
│ │ pip       mirrors.aliyun.com       [预设 ▾] ✓ │   │
│ │ cargo     rsproxy.cn               [预设 ▾] ✓ │   │
│ │ maven     maven.aliyun.com         [预设 ▾] ⚠  │   │
│ │ go / docker / nuget / gem / pub / conda ...    │   │
│ └───────────────────────────────────────────────┘   │
│ 代理设置                                            │
│ ┌ 下载代理 ──────────────────────────────────────┐   │
│ │ [x] 启用   http://127.0.0.1:7890              │   │
│ ├ 环境变量代理（HTTP_PROXY / HTTPS_PROXY ...）───┤   │
│ │ 与下载代理联动 ✓   NO_PROXY: localhost,127.*   │   │
│ ├ 系统代理 ────────────────────────────────────┤   │
│ │ 当前: 已开启 http://127.0.0.1:7890  [接管/释放]  │   │
│ └ 加速镜像 ────────────────────────────────────┘   │
│  工具下载加速镜像: [自动 ▾]  已缓存版本 6           │
└─────────────────────────────────────────────────────┘
```

**交互要点**
- 镜像区按工具分行，每行：工具名 + 当前源地址（等宽字体）+ 预设下拉 + 状态（✓ 官方/镜像 / ⚠ 冲突）+ 「设为当前」。
- 冲突（registry 基线不一致）在该行内联红字提示 + 「确认基线」按钮。
- 代理区沿用现有三层结构：下载代理 →工具/环境变量代理（联动开关）→ 系统代理（接管/释放）；NO_PROXY 编辑框。
- 加速镜像与下载代理互斥提示（二选一优先下载代理）。
- **评审修订**：镜像行列表「最近使用」自动置顶（按上次切换时间）；页顶提供「网络诊断」按钮 —— 一键探测各工具源与代理连通性，结果按行着色列出（正常 ✓ / 超时 ✗）。

**所需后端命令**：`get_registry_state`、`list_registry_presets`、`switch_registry`、`get_proxy`、`set_proxy`、`get_sys_proxy`、`set_sys_proxy`、`get_mirror_config`、`set_mirror_config`（已有）。

### 5.7 日志

**目标**：快速排障 —— 实时查看、过滤、导出。

**布局线框**

```
┌─────────────────────────────────────────────────────┐
│ 日志                                  [打开目录] [导出] │

│ │ 18:12:02 INFO  env::writer   updated JAVA_HOME │   │

│ │ 18:12:09 ERROR queue::task   node v20 下载失败  │   │
│ │ ...（等宽字体、级别着色、自动滚动）               │   │

└─────────────────────────────────────────────────────┘
```

**交互要点**
- 日志查看器：等宽字体、行级别着色（INFO 灰 / WARN 黄 / ERROR 红）、搜索高亮、自动滚动跟随新日志。
- 文件切换下拉 + 级别过滤下拉；`[暂停]` 停止自动滚动以便排查。
- `[导出]` 保存为 .log 文件（默认 `logsDir`），同时保留「复制全文」；`[打开目录]` 用系统文件管理器打开 logsDir。

- 无日志时显示空状态引导。

**所需后端命令**：`list_logs`（文件列表）、`read_logs`（内容，支持 filter）、`clear_logs`（可选）；实时可挂 `log` 事件推送（Tauri event）。
